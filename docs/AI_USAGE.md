# AI Coding 协作与校验记录

## 我的使用原则

我将 AI 用于缩短探索和实现时间，但不把 AI 输出当作事实或完成标准。AI 给出的实现只有在能够解释、能够观察、能够通过反向测试后才会保留。

AI 协助了候选方案拆解、初始代码、测试样例、文档整理和浏览器自动化验证。架构取舍、风险判断、验收条件和最终结果由我负责。

## 从 AI 产出到可信结果

1. **先观察真实输入**：检查每页文本层、方向和图片，而不是沿用“全部是扫描件”的初始假设。
2. **把建议转成可证伪假设**：例如“上传后 Agent 已切换”，需要用旧问题在新 PDF 上返回 `no_answer` 来证明。
3. **使用反向和失败测试**：除正常答案外，验证模糊问题、无答案、损坏上传、OCR 异常和缓存污染。
4. **保留原始证据**：任何自动修复都不能覆盖 OCR 原值、页码和坐标。
5. **端到端复核**：使用真实 PDF、黄金集、浏览器流程和结构化 artifacts 共同验证。

## 关键修正记录

| AI 辅助阶段的候选做法 | 我发现的风险 | 最终修正 |
| --- | --- | --- |
| 直接对全文做通用 RAG | 数字脱离表格行列后不可验证 | 建立结构化单元格证据层 |
| 将整个 PDF 都送入 OCR | 忽略已有高质量文本层，增加错误和耗时 | 逐页判断并路由解析器 |
| 自动修复明显异常的 OCR 数字 | 可能制造错误财务事实 | 保留原值并返回 `needs_review` |
| 只验证上传接口返回成功 | 可能仍使用旧知识库 | 新 PDF 上传后用旧问题做反向测试 |
| 只断言答案文本 | 可能答案碰巧正确但引用错误 | 黄金集同时断言状态、数值和页码 |

更完整的决策过程见 [工程判断与可靠性闭环](engineering-decisions.md)。

## 责任边界

AI 输出不会被视作财务事实来源。最终答案必须来自可追踪的结构化证据。我对架构取舍、代码、测试结果、边界说明和最终结果负责。
