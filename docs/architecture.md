# 设计说明

## 目标与取舍

样本的主要风险不是语言模型不会总结，而是表格数字在解析、OCR、行列映射和回答过程中被错误关联。因此原型采用“确定性工具优先，生成模型可选”的 Agent 工作流。

```text
inspect_page -> route_parser -> extract_words -> recover_table
             -> structured_retrieval -> validate_evidence -> answer/refuse
```

每一步均产出可检查 artifact，方便区分解析错误、检索错误和回答错误。

完整的观察、判断、反向验证和 AI Coding 修正过程见 [工程判断与可靠性闭环](engineering-decisions.md)。

## 数据契约

最小证据单位是 `FinancialCell`：

- `table / period / row / column`：结构化语义。
- `raw_value / numeric_value`：原值和可计算值分离。
- `pdf_page / printed_page / bbox`：可追溯引用。
- `source / confidence / warnings`：可靠性信息。

系统绝不在 OCR 结果非法时静默修正数字。修复应由独立校验、人工复核或第二 OCR 引擎完成。

## Agent 与 RAG

当前 Agent 使用显式状态和工具：

1. 问题识别期间、表格、行和列。
2. 数值问题优先结构化查询。
3. 未精确匹配时执行轻量证据检索。
4. 找到单元格后运行自检工具。
5. 根据检查结果回答、提示复核、澄清或拒答。

生产环境可以加入向量检索和 LLM 意图解析，但 LLM 输出只能生成查询条件和语言表达，不能作为财务数字来源。

## 扩展到其他业务

- 金融：增加币种、单位、勾稽关系和双 OCR 比对。
- 合规：数据契约扩展为条款编号、版本、生效日期和冲突状态。
- 合同：增加合同要素、风险规则和跨附件引用。
- 客户交付：替换 OCR/LLM Provider，不改变证据、引用和检查接口。

迁移时不直接复用当前财务行列规则，而是复用以下稳定接口：

1. 页面诊断和解析器路由接口。
2. 带页码、坐标、来源、置信度的证据契约。
3. 检索、引用、自检和回答状态机。
4. 黄金集、失败样本和回归门禁。

## 工程与安全边界

- 上传解析使用锁保护当前单文档状态，失败时恢复上一份成功 artifacts。
- Web 地址、端口和上传限制可通过环境变量配置。
- 结构化审计日志记录事件、状态、引用和耗时，不记录问题正文。
- 当前原型没有鉴权、任务队列、多租户隔离和数据保留策略，不应直接暴露到公网。
