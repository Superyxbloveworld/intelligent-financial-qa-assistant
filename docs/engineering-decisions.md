# 工程判断与可靠性闭环

## 我的核心判断

拿到样本后，我没有先接入大模型，而是先检查每页的文本层、方向、图片数量和内容结构。检查结果改变了实现方向：

- 第 1-5 页虽然存在文本层，但普通文本提取会丢失表格行列关系。
- 第 6 页没有文本层，必须使用 OCR。
- 真正高风险的环节不是答案措辞，而是 OCR 数字错误、行列错配和跨期间误关联。

因此我选择先构建可追溯的证据层，再让 Agent 基于证据回答：

```text
逐页诊断 -> 解析器路由 -> 表格结构化 -> 证据检索
        -> 引用与数值校验 -> 回答 / 复核 / 澄清 / 拒答
```

## 关键决策记录

| 观察到的问题 | 我的判断与取舍 | 如何验证 | 当前结论 |
| --- | --- | --- | --- |
| PDF 同时包含文本页和扫描页 | 不能使用单一解析器，必须逐页路由 | 检查每页原生字符数、图片数和解析器诊断 | 5 页走 PyMuPDF，1 页自动走 OCR |
| 文本提取能看到数字，但表格关系丢失 | 数字问答必须恢复行、列、期间和页码，不能仅做文本切块 | 将单元格保存为带坐标和来源的 `FinancialCell`，抽查页面证据 | 恢复 446 个可追溯单元格 |
| OCR 可能把标点和数字识别错误 | 不自动猜测或修正财务数字；保留原值并降低状态 | 数字格式、OCR 置信度、行合计一致性检查 | 异常答案返回 `needs_review` |
| 用户问题可能缺少期间或文档没有答案 | “有结果”不等于“可回答”，需要显式状态机 | 黄金集覆盖模糊问题与无答案问题 | 返回澄清或拒答，不补全文档外事实 |
| 上传新 PDF 可能污染旧知识库 | 文档切换必须清理旧页面、重建证据；失败时回滚 | 上传一页普通 PDF 后，旧财务答案必须失效 | 自动化测试确认返回 `no_answer` |
| 页面能运行不代表结果可靠 | 测试必须同时检查状态、精确数值、引用页码和风险标记 | 单元测试、真实 PDF 集成、黄金集和解析检查 | `17 passed`，黄金集 `10/10` |

## AI Coding 中的个人判断

AI 主要用于加速候选实现、测试样例和文档整理；我将它视为“提出可验证假设的协作者”，而不是决策者。

### 迭代 1：从全文 RAG 转向证据优先

- **初始假设**：提取全文、切块后即可问答。
- **实际观察**：财务表格中的数字脱离行列后没有可靠语义。
- **我的修正**：将最小证据单位改为结构化单元格，保存期间、行、列、页码、坐标、来源和置信度。
- **验证证据**：回答可定位到具体 `cell_id` 和来源页；引用页码进入黄金集断言。

### 迭代 2：从“统一解析”转向逐页路由

- **初始假设**：样本是扫描 PDF，应全部 OCR。
- **实际观察**：第 1-5 页存在高质量文本层，仅第 6 页需要 OCR。
- **我的修正**：增加逐页类型判断，优先使用原生坐标文本，只对扫描页 OCR。
- **验证证据**：`diagnostics.json` 显示每页选择的解析器及原因。

### 迭代 3：从“修正 OCR 数字”转向显式不确定性

- **初始诱惑**：根据上下文自动修复类似 `26.075,352,739.73` 的异常数字。
- **风险判断**：自动修复会制造无法证明的财务事实。
- **我的修正**：保留 OCR 原值，增加格式、置信度和勾稽检查，回答状态降为 `needs_review`。
- **验证证据**：对应黄金问题明确断言状态和引用页码。

### 迭代 4：从“上传成功”转向文档切换一致性

- **发现的问题**：上传接口成功并不能证明 Agent 已切换到新知识库。
- **我的修正**：增加反向测试，上传不含财务表格的新 PDF 后，再询问旧样本问题。
- **验证证据**：旧问题返回 `no_answer`；解析失败时 artifacts 自动回滚。

## 可靠性闭环

系统把错误定位到不同阶段，而不是只观察最终回答：

| 阶段 | 可观察结果 | 失败时的行为 |
| --- | --- | --- |
| 页面检测 | `diagnostics.json` | 标记 OCR 不可用或没有提取结果 |
| 表格恢复 | `cells.jsonl` | 保留来源、坐标、原值和告警 |
| 数值校验 | `validation_report.json` | 降低置信度或要求复核 |
| 问答 | 回答状态、引用、自检、检索证据 | 澄清、拒答或 `needs_review` |
| 回归 | 单元测试、真实样本、黄金集 | 阻止状态、数值或引用错误进入演示 |
| 运行 | `events.jsonl` | 定位解析、上传、问答状态和耗时 |

## 当前边界与下一步判断

- 当前财务行列解析器针对本样本结构有效；迁移到合同或合规文档时，应复用证据、引用、自检和评估接口，而不是复用财务 schema。
- 当前使用 macOS Vision 降低本地复现成本；生产环境应替换为可部署 OCR，并增加双引擎比对。
- 当前优先完成单文档可靠闭环；多文档索引、鉴权、异步任务和人工复核后台应在真实交付阶段补充。
