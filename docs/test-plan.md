# 测试与评估说明

## 测试策略

测试不是按模块机械补齐，而是从“什么错误可能让系统给出看似合理但实际错误的答案”反推。正常回答只是最低要求，更重要的是验证系统在证据不足、解析异常和状态切换时不会悄悄出错。

| 失效模式 | 为什么危险 | 验证方式 | 期望行为 |
| --- | --- | --- | --- |
| 数字解析错误但回答措辞正常 | 用户很难从自然语言发现财务数字已错 | 非法标点、低置信度、合计勾稽测试 | `needs_review`，保留原值 |
| 答案正确但引用页错误 | 无法审计，可能是碰巧命中 | 黄金集同时断言数值和页码 | 引用必须与答案证据一致 |
| 模糊问题被强行回答 | 可能混淆 2024 与 2025 期间 | 缺少期间的问题 | `clarification_required` |
| 文档没有答案却生成内容 | 形成典型幻觉 | 无答案黄金问题 | `no_answer` |
| 新 PDF 上传后仍使用旧证据 | 页面看似切换，实际回答污染 | 上传普通 PDF 后询问旧问题 | 旧答案失效 |
| 上传解析失败破坏当前知识库 | 一次失败导致服务不可用 | 损坏 PDF 上传测试 | 拒绝上传并保留旧文档 |
| 扫描页被当作普通文本页 | 页面内容完全遗漏 | 真实样本逐页诊断断言 | 自动路由至 OCR |

## 测试分层

### 单元测试

- 财务数字：千分位、括号负数、空值、非法 OCR 标点。
- 坐标分行：不依赖 PDF 原始提取顺序。
- Agent 行为：有答案、缺少期间、文档无答案。
- 自检：低置信度和行合计一致性。
- 审计日志：写入结构化事件，且不保存问题正文。

### Web 与文档切换测试

- 损坏 PDF 被拒绝，且当前成功文档不被破坏。
- 上传有效新 PDF 后自动重新解析并切换 Agent。
- 上传不含财务表格的新 PDF 后，旧样本答案不能继续命中，必须返回 `no_answer`。
- 可一键恢复内置样本。

### 黄金集评估

`eval/golden_questions.jsonl` 覆盖：

- 第 5 页原生文本表格。
- 第 6 页扫描 OCR 表格。
- 2025/2024 跨期间问题。
- 其他综合收益多级表头问题。
- 缺少期间的模糊问题。
- 文档中不存在答案的问题。

评估同时检查状态、答案值和来源页码，避免“答案碰巧正确但引用错误”。

### 解析质量检查

`artifacts/validation_report.json` 汇总：

- 单元格数量与警告类型。
- 数字格式失败。
- OCR 低置信度。
- 行合计不一致。
- 失败单元格的页码、行、列和 `cell_id`。

## 回归标准

完整回归运行：

```bash
make all
```

验收条件：

- 所有单元测试和真实样本集成测试通过。
- 黄金集状态、值和引用页码全部通过。
- 扫描页被路由到 OCR，而不是错误标记为原生文本页。
- 非法 OCR 数字进入 `needs_review`，不得静默生成可信答案。
- 新 PDF 上传后不得继续返回旧文档答案，避免缓存污染或硬编码。
- 上传失败必须回滚，不能破坏上一份成功证据库。
- `artifacts/events.jsonl` 可用于定位解析、上传和问答事件，同时不保存问题正文。
