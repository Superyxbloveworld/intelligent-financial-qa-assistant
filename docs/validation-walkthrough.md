# 可靠性验证操作路径

1. 展示 README、架构图和目录结构。
2. 执行 `make ingest`，说明第 1-5 页与第 6 页采用不同解析路由。
3. 执行 `make report && make run`，打开 `/reliability?section=parse` 展示正文页、扫描页诊断和结构化单元格。
4. 提问 2025 短期借款合计，展示结构化答案、引用页码和自检。
5. 提问 2024 短期借款合计，展示扫描页 OCR 结果。
6. 提问其他综合收益期末余额，展示多级表头问答。
7. 提问“短期借款是多少”，展示澄清。
8. 提问营业收入，展示无答案拒答。
9. 打开 `/reliability?section=checks` 展示引用、自检和 OCR 风险。
10. 打开 `/reliability?section=test` 展示测试与黄金集结果。
11. 打开 `/reliability?section=reasoning`，说明哪些真实观察推翻了初始假设，以及如何通过反向测试和运行证据修正方案。

演示中重点讲清楚：

- 为什么从通用全文 RAG 转向结构化证据优先。
- 为什么只对第 6 页 OCR，以及逐页路由如何降低错误和成本。
- 为什么不自动修复异常财务数字，而是返回 `needs_review`。
- 为什么“上传成功”还不够，需要用旧问题验证知识库切换。
- 为什么黄金集必须同时断言状态、数值和引用页码。
